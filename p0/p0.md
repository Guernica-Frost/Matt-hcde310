## Resource 1: Open-Meteo

**What it provides** (1–2 sentences):

Open-Meteo provides the weather forecasts for a location by using its latitude and longitude, including temperature, precipitation, and wind speed. It also provides current conditions based on the model they have. Students could use this data to plan their commute.

**Docs link:** https://open-meteo.com/en/docs

**Access:**

API key: The API is free if it's not for business purpose. So no API key is needed for this project.
Rate limits: stay below 600 calls per minute, 5,000 per hour, and 10,000 per day; the pricing page also lists a 300,000-call monthly allowance.
Cost: none for this non-commercial purpose. Commercial use requires a paid plan.

**Sample response** (trim it to a few fields; paste the URL you called too):

URL: https://api.open-meteo.com/v1/forecast?latitude=47.6062&longitude=-122.3321&current=temperature_2m,precipitation,wind_speed_10m&timezone=America%2FLos_Angeles

```json
{
  "timezone": "America/Los_Angeles",
  "current_units": {
    "temperature_2m": "°C",
    "precipitation": "mm",
    "wind_speed_10m": "km/h"
  },
  "current": {
    "time": "2026-10-27T22:00",
    "temperature_2m": 8.7,
    "precipitation": 0.0,
    "wind_speed_10m": 21.4
  }
}
```

**Who could this data help, and with what?** (2–3 ideas)

1. First-year UW students who walk to classes could check the forecast to decide whether to bring an umbrella.
2. Students who bike to campus can compare hourly rain and wind forecasts to schedule leaving time or consider taking the bus.
3. Student club officers can check the forecast when choosing a time for an outdoor meetup and deciding whether to arrange an indoor backup.

**One risk** (missing data, bias, privacy, or reliability):

Reliability: forecasts and current conditions are based on weather models, so they may miss rain or wind at a particular campus location.

## Resource 2: Open Library

**What it provides** (1–2 sentences):

Open Library provides searchable book records with information such as titles, authors, first publication years, and work identifiers. Its Search API could support a book discovery tool for students and reading groups.

**Docs link:** https://openlibrary.org/dev/docs/api/search

**Access:**

API key: We don’t need an API key or an account to search for books.
Rate limits: 1 request per second by default, or 3 requests per second for requests identified with an application name and contact email in the 'User-Agent' header.
Cost: none for this project.

**Sample response** (trim it to a few fields; paste the URL you called too):

URL: https://openlibrary.org/search.json?title=the+hobbit&author=tolkien&fields=key,title,author_name,first_publish_year&limit=1

```json
{
  "docs": [
    {
      "author_name": ["J.R.R. Tolkien"],
      "first_publish_year": 1937,
      "key": "/works/OL27482W",
      "title": "The Hobbit"
    }
  ]
}
```

**Who could this data help, and with what?** (2–3 ideas)

1. Students who remember only part of a book title or the author's name could search for the complete title and author before looking for the book at a library.
2. Campus book clubs can collect titles, authors, and publication years to make a shortlist for members to vote on.
3. Students who enjoy a particular author could explore that author's other books and build a personal reading list.

**One risk** (missing data, bias, privacy, or reliability):

Some records may lack fields or represent different editions of the same book.
